# Interactive Hermes Dashboard

**Mission:** `AGENT_FRAMEWORK`  
**Revision:** `2026-09-10-r2`  
**Gap:** `AGENT-R1-GAP-05`  
**Status:** candidate; user-facing enablement is held until exact-head CI and fresh external review pass.

## Purpose

The first human-facing Agent capability is the **native Hermes Web Dashboard** running on Modal. It is not a new runtime or framework layer.

```text
phone / browser
    |
    v
native Hermes Web Dashboard
Nous Portal OAuth gate
    |
    v
GitHub-owned Hermes managed policy
    |
    v
protected FreeLLMAPI Modal endpoint
    |
    v
configured free-provider pool
```

Interactive session and memory state belongs only to Hermes. It is not Control state, not a framework task database, and not target-project business truth.

## Exact runtime boundary

- Hermes stays pinned to commit `2237be355906fbe6065ce1815711eee52b2d646e`.
- The dashboard is started with upstream `hermes dashboard`; there is no local UI fork.
- The upstream web frontend is built from its own lockfile using checksum-pinned Node `22.22.0`.
- FreeLLMAPI remains the only inference gateway.
- The dashboard receives only the FreeLLMAPI client credential, Modal proxy credential and the OAuth client id.
- Direct upstream provider credential names are pinned empty in Hermes managed scope and therefore cannot be persisted through the native key writer.
- One dashboard container is allowed. There is no framework queue, DB, scheduler or second Control lifecycle.

## GitHub-managed effective policy

`runtime/hermes-managed-config.json` is copied to `/etc/hermes/config.yaml`, the native Hermes managed-scope location. Managed values override user/profile values and are immutable through Hermes config writers.

The policy pins:

- model route: `provider=freellmapi`, `model=auto`;
- configured provider set: FreeLLMAPI only;
- interactive toolsets: `web`, `memory`, `session_search`;
- approval mode: `manual`;
- SQLite journal mode: `delete` for the single-writer mounted-volume topology.

Not authorized in interactive Hermes: terminal/shell, file mutation, browser/computer automation, delegation/swarm, messaging, project production credentials or direct model-provider credentials.

`runtime/hermes-managed.env` contains **empty** administrator-managed names for direct-provider API credentials. Its purpose is deny-by-ownership: no credential value is stored in Git.

## Authentication

A non-loopback native Hermes dashboard must be authenticated. This deployment uses the pinned Hermes **Nous Portal OAuth** provider because the Modal endpoint is internet-facing.

Required Modal Secret:

```text
name: agent-hermes-dashboard
key:  HERMES_DASHBOARD_OAUTH_CLIENT_ID
value shape: agent:{instance_id}
```

The OAuth client id is externally provisioned. It is intentionally not generated by repository code and not committed to Git.

The dashboard must fail closed when the OAuth client id is absent or malformed. Basic username/password auth is not the default for the public Modal endpoint.

## Persistence and concurrency

`agent-hermes-dashboard-state` is a dedicated Modal Volume mounted at `/root/.hermes`.

- `max_containers=1` prevents competing dashboard writers.
- Hermes uses SQLite `journal_mode=delete` on the mounted state.
- the container commits the Volume every 30 seconds;
- a normal cold restart can therefore lose at most the uncommitted interval;
- Control never reads or writes this Volume.

This persistence is for interactive Hermes sessions/memory only. It must never become a target-project source of truth.

## Cold start

The dashboard scales to zero. A cold request may need to start the Modal container and Hermes process. The native frontend is prebuilt into the image, so cold start does not run npm or fetch JavaScript dependencies.

The dashboard startup sequence is fail-closed:

1. resolve the deployed protected FreeLLMAPI endpoint internally;
2. prove the gateway responds under the existing bearer + Modal proxy credentials;
3. validate the repository-managed policy and direct-provider deny surface;
4. validate the OAuth client id;
5. start native `hermes dashboard --host 0.0.0.0 --port 9119 --no-open`.

Failure in steps 1-4 means no dashboard starts.

## Security verification

Candidate CI verifies:

- policy/provider/toolset drift fails closed;
- direct-provider credentials present in the dashboard environment are rejected;
- missing gateway credentials are rejected;
- missing/malformed OAuth client id is rejected;
- the managed env deny surface exactly covers the declared direct-provider credential set;
- exact pinned Hermes exposes the native dashboard command;
- exact pinned Hermes managed scope overrides a user provider/toolset setting;
- exact pinned Hermes treats a managed direct-provider env name as immutable;
- existing bounded-worker and real Hermes → FreeLLMAPI runtime probes continue to pass.

A fresh **external exact-candidate review** is mandatory before user-facing enablement.

## Deployment / enablement

`.github/workflows/deploy-modal.yml` remains the single deployment path and is explicit-dispatch only. Merging source does not automatically expose the dashboard.

Before the first dashboard deployment an operator must provision `agent-hermes-dashboard` with the Nous Portal OAuth client id. After deployment verify from a mobile browser:

1. unauthenticated dashboard access is redirected/rejected by the Hermes auth gate;
2. valid owner login succeeds;
3. `/api/status` reports authentication required and the expected OAuth provider;
4. a simple public/non-personal chat turn routes through FreeLLMAPI;
5. session history survives a normal container recycle within the documented persistence interval;
6. attempts to switch the effective provider/toolset or persist a direct-provider credential are rejected/ineffective.

No target-project production action is part of this proof.

## Governed task boundary

Interactive chat is a user capability, not autonomous project authority. If a later feature allows the dashboard to request framework work, it must submit through the same governed task/authority contract as any other caller. The dashboard may never self-issue Control acceptance, project `DONE`, production credentials or irreversible business authority.
